# Getting Started with ac-guard

A 15-minute tutorial that takes a Python project from zero to guarded — rule
document for your AI agent, pre-commit hooks, and runtime interception all
wired up from a single `guard.yaml`.

> **Prefer Chinese?** See [getting-started_zh.md](getting-started_zh.md).

---

## Prerequisites

- Python **3.10 or newer** (`python --version`)
- A project inside a git repository (`git init` is enough)
- [`ruff`](https://docs.astral.sh/ruff/) on your `PATH` (`pip install ruff`) —
  used as the example check in Step&nbsp;3
- A target agent to guard — this guide targets **Claude Code**. The agent
  itself does not need to be installed on your machine for `ac-guard install`
  to work; it just generates the files the agent would read.

## 1. Install the CLI

```bash
pip install ac-guard
ac-guard --version
```

Expected output:

```
ac-guard 0.1.0 — AI Code Guard
```

The executable is `ac-guard` (short for **AI Code Guard**). The Python package
name is `ac_guard` and the configuration file is `guard.yaml` — those stay
stable even if the CLI alias changes.

## 2. Create guard.yaml

```bash
cd your-python-project
ac-guard init --language python --preset minimal
```

You should see:

```
Created guard.yaml

Next steps:
  1. Review and edit the configuration file
  2. Run 'ac-guard install --agent <agent>' to generate artifacts
```

`ac-guard init` supports three presets. Pick the one that fits your team:

| Preset | Commit checks | Push checks | Behavior rules | Audit log |
|---|---|---|---|---|
| `minimal` | format | `pytest` | built-in only | off |
| `standard` | format + naming | lint + `pytest --cov` | built-in only | on |
| `strict` | format + naming | lint + `pytest --cov` with threshold + `bandit` | `.env*`, credentials blocked | on + PR report |

This tutorial uses `minimal` and builds it up explicitly so you can see what
each piece does.

## 3. Understand guard.yaml

Open the generated file:

```yaml
# AI Code Guard configuration
# Generated by ac-guard 0.1.0
# Preset: minimal

version: 1

project:
  name: your-python-project
  language: python

code:
  commit:
    format: true
  push:
    checks:
      test:
        command: pytest
        pass_filenames: false

output:
  audit:
    enabled: false
```

The four top-level sections you need to know:

- **`project`** — identity. Auto-detected from the current directory.
- **`behavior`** — runtime rules evaluated by the agent hook. Your minimal
  preset has **no user-authored rules** in this section, but ac-guard still
  injects four **system protection rules** so the agent cannot silently
  rewrite its own guardrails (`guard.yaml`, `.ac-guard/**`,
  `.pre-commit-config.yaml`, `.git/hooks/**` — all marked `require_approval`).
  You'll see them in the `CLAUDE.md` generated by Step&nbsp;4, and you'll add
  your own rule in Step&nbsp;6.
- **`code`** — quality gates grouped by `commit` and `push` stage. Each stage
  accepts built-in shortcuts (`format`, `naming`, `lint`) **and** free-form
  `checks` keyed by command.
- **`output`** — where results go (terminal, audit log, PR comments).

> **0.1.0 note.** The built-in `format` / `naming` / `lint` shortcuts currently
> depend on language-specific hook wiring that is being completed in a
> follow-up release. For a reliable out-of-the-box experience, this tutorial
> disables those shortcuts and defines an explicit `ruff` check instead. The
> pattern you'll learn — custom `checks` entries — is the durable one.

Replace the `code:` block with:

```yaml
code:
  commit:
    format: false
    naming: false
    checks:
      ruff:
        command: "ruff check src/"
        pass_filenames: false
        types: ["python"]
  push:
    lint: false
    checks:
      test:
        command: pytest
        pass_filenames: false
```

Save.

## 4. Install agent artifacts

```bash
ac-guard install --agent claude-code
```

You should see:

```
AI Code Guard installed for: claude-code

Generated 6 artifact(s):
  .ac-guard/policy.json
  .claude/hooks/interceptor.py
  .git/hooks/pre-commit
  .git/hooks/pre-push
  .pre-commit-config.yaml
  CLAUDE.md
```

Your project directory now looks like this:

```
your-python-project/
├── guard.yaml                  # source of truth (you edit this)
├── CLAUDE.md                   # behavior rules for Claude Code
├── .pre-commit-config.yaml     # generated hook manifest
├── .ac-guard/
│   ├── state.json              # install state (agents, artifacts)
│   └── policy.json             # runtime policy cache
├── .claude/hooks/interceptor.py  # Claude Code pre_tool_use hook
└── .git/hooks/
    ├── pre-commit              # → ac-guard gate run --stage commit
    └── pre-push                # → ac-guard gate run --stage push
```

Every file above is **managed**: re-running `ac-guard install` or
`ac-guard update` regenerates them from `guard.yaml`. Edit `guard.yaml` and
regenerate rather than touching the generated files. (Exception: `CLAUDE.md`
has `<!-- AI-GUARD:BEGIN -->` / `<!-- AI-GUARD:END -->` markers — only the
content between them is regenerated, so you can add free-form sections
outside the markers and they'll be preserved.)

Peek inside `CLAUDE.md`. Even though your `guard.yaml` has no `behavior`
section yet, the managed block already contains a **Require Approval** list
with four entries — these are the system protection rules mentioned in
Step&nbsp;3. They protect the guardrails themselves from accidental
overwrites.

Want a different agent? `ac-guard agents` lists what each supports:

```
Agent Capability Matrix
------------------------------------------------------------------------
Agent         Block   Ask     Rule Doc                          Status
------------------------------------------------------------------------
claude-code   yes     yes     CLAUDE.md                         INSTALLED
copilot       no      no      .github/copilot-instructions.md   -
cursor        yes     no      .cursor/rules/behavior.mdc        -
kilocode      no      no      .kilocode/rules/behavior.md       -
opencode      yes     yes     AGENTS.md                         -
```

Agents with `Block`/`Ask` support get runtime interception. Agents without
still receive the behavior rules as soft constraints in their rule document.

## 5. Run your first check

```bash
git add -A
ac-guard check
```

On a clean codebase:

```
Stage: commit — PASSED

  [PASS] ruff (37ms)

1/1 checks passed, 0 failed
Total time: 54ms
```

Now introduce a deliberate mistake. Create `src/bad.py`:

```python
def bad( x,y ):
```

Stage and re-run:

```bash
git add -A
ac-guard check
```

```
Stage: commit — FAILED

  [FAIL] ruff (19ms)

0/1 checks passed, 1 failed
Total time: 58ms
```

For the actual violations, switch to the machine-readable format:

```bash
ac-guard check --format json
```

```json
{
  "stage": "commit",
  "passed": false,
  "results": [
    {
      "name": "ruff",
      "passed": false,
      "duration_ms": 11,
      "output": "invalid-syntax: Expected an indented block after function definition\n --> src/bad.py:1:16\n..."
    }
  ]
}
```

Delete `src/bad.py` and re-check — you're green again. The same
`ac-guard check` runs automatically when you `git commit`, because the
generated `.git/hooks/pre-commit` invokes it.

If you want to stop agents from skipping the gate with
`git commit --no-verify`, add an execute rule as shown in Step&nbsp;6 — none
of the built-in presets ship this rule today, so you opt in explicitly.

## 6. Add a custom behavior rule

Suppose your project stores Terraform under `terraform/prod/` and you don't
want any agent writing there, even by accident. Add a rule to `guard.yaml`:

```yaml
behavior:
  write:
    forbidden:
      - pattern: "file:terraform/prod/**"
        reason: "Production infrastructure is protected"
```

Then regenerate:

```bash
ac-guard update
```

```
Updated 6 artifact(s) for agents: claude-code
```

Two things happen under the hood:

1. `.ac-guard/policy.json` (the runtime policy) now contains your new
   forbidden pattern.
2. `CLAUDE.md` gains a line under **Write Operations — Forbidden** describing
   the rule in natural language.

When the Claude Code agent next tries to write under `terraform/prod/`, its
`pre_tool_use` hook looks up the policy, matches your pattern, and returns
`deny` with your `reason` string.

The same structure works for commands via `behavior.execute.forbidden` — for
example, to block the hook-bypass trick mentioned in Step&nbsp;5:

```yaml
behavior:
  execute:
    forbidden:
      - pattern: "shell:git commit --no-verify*"
        reason: "Bypassing the guard hook is not allowed"
```

A few things to know about patterns:

- **Scheme prefix is required**: `file:`, `shell:`, `mcp:`, or `web:`. This
  tells the matcher which dimension (path, command, MCP tool, URL) to check.
- **Priority**: `forbidden` > `require_approval` > `allow` > default allow.
- **Regex**: add `regex: true` if you need regex instead of glob.

The full schema lives in
[`design/AI_GUARD_SYSTEM_DESIGN.md`](../design/AI_GUARD_SYSTEM_DESIGN.md).

## 7. (Optional) Use a shared ruleset

Teams often want one canonical set of guard rules that every project pulls
in. That's what rulesets are for:

```bash
ac-guard ruleset fetch https://github.com/your-team/rules.git#v1.0
ac-guard ruleset list
```

The ruleset lands in `.ac-guard/cache/<name>/`. Reference it from your
`guard.yaml`:

```yaml
rulesets:
  - <name>
```

Then `ac-guard update` to regenerate artifacts with the merged ruleset
rules applied on top of your own.

`ac-guard ruleset show <name>` prints the ruleset's behavior rules and check
scripts. `ac-guard ruleset cache clear` wipes the local cache.

## Troubleshooting

**`ac-guard install` warns "no .git/ directory"** — run it from the repo
root. If your repo isn't initialised yet, `git init` first.

**`pre-commit not installed`** on a check run — install it (`pip install
pre-commit`) or rely on custom `checks` entries as this tutorial does.

**A check shows `[FAIL] pre-commit:format`** — this is the 0.1.0 built-in
shortcut mismatch noted in Step 3. Set `format: false` / `naming: false` /
`lint: false` and use explicit `checks` instead.

**`ac-guard status` reports drift** — you edited a generated file. Run
`ac-guard update` to bring artifacts back in sync with `guard.yaml`.

**Wrong agent got installed** — artifacts are per-agent. Run
`ac-guard uninstall --agent <name>` then `ac-guard install --agent <the-right-one>`.
