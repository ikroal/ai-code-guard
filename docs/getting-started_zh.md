# 快速上手 ac-guard

一份 15 分钟的教程，带你把一个 Python 项目从零接入看护 —— 基于单一的
`guard.yaml` 生成 Agent 规则文档、pre-commit 钩子和运行时拦截。

> **English version**: [getting-started.md](getting-started.md)

---

## 前置条件

- Python **3.10 及以上**（`python --version`）
- 已初始化的 git 仓库（`git init` 过即可）
- `PATH` 中可用的 [`ruff`](https://docs.astral.sh/ruff/)（`pip install ruff`）
  —— 第 3 步作为示例 check 用到
- 一个目标 Agent —— 本教程的目标是 **Claude Code**。你本机**不必**实际装
  Claude Code：`ac-guard install` 只生成 Agent 会读取的规则文件

## 1. 安装 CLI

```bash
pip install ac-guard
ac-guard --version
```

预期输出：

```
ac-guard 0.1.0 — AI Code Guard
```

可执行程序名是 `ac-guard`（AI Code Guard 的缩写）。Python 包名为
`ac_guard`，配置文件名为 `guard.yaml` —— 即便未来 CLI 别名调整，这两个名字
保持稳定。

## 2. 生成 guard.yaml

```bash
cd your-python-project
ac-guard init --language python --preset minimal
```

你会看到：

```
Created guard.yaml

Next steps:
  1. Review and edit the configuration file
  2. Run 'ac-guard install --agent <agent>' to generate artifacts
```

`ac-guard init` 提供三种预设，按团队诉求挑选：

| 预设 | 提交检查 | 推送检查 | 行为规则 | Audit log |
|---|---|---|---|---|
| `minimal` | format | `pytest` | 仅内置 | 关 |
| `standard` | format + naming | lint + `pytest --cov` | 仅内置 | 开 |
| `strict` | format + naming | lint + 含阈值的 `pytest --cov` + `bandit` | 阻止 `.env*`、credentials | 开 + PR 评论 |

本教程从 `minimal` 出发，逐步手动增补，方便你看清每一部分的作用。

## 3. 理解 guard.yaml

打开刚生成的文件：

```yaml
# AI Code Guard configuration
# Generated by ac-guard 0.1.0
# Preset: minimal

version: 1

project:
  name: your-python-project
  language: python

code:
  commit:
    format: true
  push:
    checks:
      test:
        command: pytest
        pass_filenames: false

output:
  audit:
    enabled: false
```

你上面这份文件里出现了三个顶层段落：`project` / `code` / `output`。还有
第四个段落 `behavior` 是可选的，minimal 预设里省略了，你会在第 6 步加
上。各段用途如下：

- **`project`**：项目身份，init 会从当前目录自动填充
- **`code`**：代码质量门禁，按 `commit` / `push` 阶段划分。每个阶段支持
  内置快捷开关（`format`、`naming`、`lint`）**与** 自定义 `checks` 两种方式
- **`output`**：结果去向（终端、audit 日志、PR 评论）
- **`behavior`**（*可选，当前文件里还没有*）：运行时行为规则，由 Agent
  的 hook 求值。即便你没写这个段落，ac-guard 也会注入 **4 条系统保护
  规则**，避免 Agent 悄悄改掉自己的护栏（`guard.yaml` / `.ac-guard/**` /
  `.pre-commit-config.yaml` / `.git/hooks/**`，均为 `require_approval`）。
  这几条会出现在第 4 步生成的 `CLAUDE.md` 里

> **0.1.0 提示**：`format` / `naming` / `lint` 三个内置快捷开关当前依赖的
> 语言特定钩子接线将在后续版本补齐。为了让你拿到开箱即用的体验，本教程
> 关掉这三个快捷开关，显式定义一个 `ruff` check。你学到的"自定义
> `checks`"模式才是长期稳定的用法。

把 `code:` 一段替换为：

```yaml
code:
  commit:
    format: false
    naming: false
    checks:
      ruff:
        command: "ruff check src/"
        pass_filenames: false
        types: ["python"]
  push:
    lint: false
    checks:
      test:
        command: pytest
        pass_filenames: false
```

保存。

## 4. 安装 Agent 工件

```bash
ac-guard install --agent claude-code
```

输出：

```
AI Code Guard installed for: claude-code

Generated 6 artifact(s):
  .ac-guard/policy.json
  .claude/hooks/interceptor.py
  .git/hooks/pre-commit
  .git/hooks/pre-push
  .pre-commit-config.yaml
  CLAUDE.md
```

你的项目目录现在长这样：

```
your-python-project/
├── guard.yaml                    # 单一配置源（只改这个）
├── CLAUDE.md                     # 给 Claude Code 看的行为规则
├── .pre-commit-config.yaml       # 生成的钩子清单
├── .ac-guard/
│   ├── state.json                # 安装状态（agents、工件清单）
│   └── policy.json               # 运行时策略缓存
├── .claude/hooks/interceptor.py  # Claude Code pre_tool_use hook
└── .git/hooks/
    ├── pre-commit                # → ac-guard gate run --stage commit
    └── pre-push                  # → ac-guard gate run --stage push
```

上面每个文件都是 **由工具管理** 的：重跑 `ac-guard install` 或
`ac-guard update` 会从 `guard.yaml` 重新生成。建议改 `guard.yaml` 再 regen，
别直接动生成文件。（例外：`CLAUDE.md` 有
`<!-- AI-GUARD:BEGIN -->` / `<!-- AI-GUARD:END -->` 标记块，只有标记之间
的内容会被重新生成。标记之外你可以自由写东西，会被保留。）

打开 `CLAUDE.md` 看一眼：即便你当前的 `guard.yaml` 没写 `behavior` 段，
managed block 里已经有一条 **Require Approval** 列表，包含 4 条 ——
就是第 3 步提到的系统保护规则，用来保护护栏本身不被误改。

想换 Agent？`ac-guard agents` 列出各自的能力：

```
Agent Capability Matrix
------------------------------------------------------------------------
Agent         Block   Ask     Rule Doc                          Status
------------------------------------------------------------------------
claude-code   yes     yes     CLAUDE.md                         INSTALLED
copilot       no      no      .github/copilot-instructions.md   -
cursor        yes     no      .cursor/rules/behavior.mdc        -
kilocode      no      no      .kilocode/rules/behavior.md       -
opencode      yes     yes     AGENTS.md                         -
```

支持 `Block`/`Ask` 的 Agent 可做运行时拦截；不支持的 Agent 则把行为规则
当作软约束写进规则文档。

## 5. 第一次 check

```bash
git add -A
ac-guard check
```

干净代码上的输出：

```
Stage: commit — PASSED

  [PASS] ruff (37ms)

1/1 checks passed, 0 failed
Total time: 54ms
```

故意造一个错误：新建 `src/bad.py`

```python
def bad( x,y ):
```

暂存后再跑：

```bash
git add -A
ac-guard check
```

```
Stage: commit — FAILED

  [FAIL] ruff (19ms)

0/1 checks passed, 1 failed
Total time: 58ms
```

想看具体违规，用机器可读格式：

```bash
ac-guard check --format json
```

```json
{
  "stage": "commit",
  "passed": false,
  "results": [
    {
      "name": "ruff",
      "passed": false,
      "duration_ms": 11,
      "output": "invalid-syntax: Expected an indented block after function definition\n --> src/bad.py:1:16\n..."
    }
  ]
}
```

删掉 `src/bad.py` 再 check —— 又变绿了。你 `git commit` 时这套
`ac-guard check` 会自动运行，因为生成的 `.git/hooks/pre-commit` 会调用
它。

想不让 Agent 用 `git commit --no-verify` 绕过门禁？按第 6 步的写法加一条
execute 规则即可。注意：当前几个内置预设都**没有**自带这条，需要你显式
开启。

## 6. 添加自定义行为规则

假设你的项目把 Terraform 放在 `terraform/prod/`，绝不希望 Agent 误写。
在 `guard.yaml` 添加：

```yaml
behavior:
  write:
    forbidden:
      - pattern: "file:terraform/prod/**"
        reason: "Production infrastructure is protected"
```

再次生成：

```bash
ac-guard update
```

```
Updated 6 artifact(s) for agents: claude-code
```

背后发生了两件事：

1. `.ac-guard/policy.json`（运行时策略）里新增你的 forbidden 模式
2. `CLAUDE.md` 在 **Write Operations — Forbidden** 一节多了一行自然语言
   描述

当 Claude Code 下次尝试写 `terraform/prod/` 下的文件，它的
`pre_tool_use` hook 会查策略、匹上你的模式，返回 `deny`，并把
`reason` 字段告诉用户。

同一套结构走 `behavior.execute.forbidden` 就能拦命令 —— 比如封掉第 5 步
提到的绕过技巧：

```yaml
behavior:
  execute:
    forbidden:
      - pattern: "shell:git commit --no-verify*"
        reason: "Bypassing the guard hook is not allowed"
```

关于 pattern 的几点要知道：

- **必须带 scheme 前缀**：`file:`、`shell:`、`mcp:` 或 `web:`。它告诉匹配
  器检查哪个维度（路径、命令、MCP 工具、URL）
- **优先级**：`forbidden` > `require_approval` > `allow` > 默认放行
- **正则**：需要正则时加 `regex: true`（默认是 glob）

完整 schema 见
[`design/AI_GUARD_SYSTEM_DESIGN.md`](../design/AI_GUARD_SYSTEM_DESIGN.md)。

## 7. （可选）使用共享 ruleset

团队经常希望有一套所有项目都引用的标准规则。ruleset 就是为此而生：

```bash
ac-guard ruleset fetch https://github.com/your-team/rules.git#v1.0
ac-guard ruleset list
```

Ruleset 会缓存到 `.ac-guard/cache/<name>/`。在 `guard.yaml` 里引用：

```yaml
rulesets:
  - <name>
```

然后 `ac-guard update` 重新生成工件，ruleset 的规则会合并到你自己的规则
之上。

`ac-guard ruleset show <name>` 打印 ruleset 内的行为规则和检查脚本；
`ac-guard ruleset cache clear` 清空本地缓存。

## 排障

**`ac-guard install` 提示 "no .git/ directory"** —— 从仓库根目录运行；仓库
没初始化就先 `git init`。

**某次 check 显示 `pre-commit not installed`** —— 装一下 pre-commit
（`pip install pre-commit`），或者像本教程这样用 custom `checks`。

**check 里出现 `[FAIL] pre-commit:format`** —— 即第 3 步提到的 0.1.0 快捷
开关限制。把 `format: false` / `naming: false` / `lint: false` 并改用显式
`checks`。

**`ac-guard status` 报 drift** —— 你手工改了生成的文件。`ac-guard update`
一键回到同步。

**装错了 Agent** —— 工件按 Agent 分组：先
`ac-guard uninstall --agent <name>`，再 `ac-guard install --agent <对的那个>`。
